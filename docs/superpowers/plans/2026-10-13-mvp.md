# Nutrition Photo Coach Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans for inline execution. User requested direct implementation; preserve current execution and do not stop for repeated design approval.

**Goal:** 建立可保存及修正餐點的繁中手機 Mock AI PWA 原始碼。

**Architecture:** 純營養模組 + Zod 邊界驗證 + Dexie 儲存；React 使用共享模型。PWA 快取 app shell；無外部 AI 呼叫。

**Tech Stack:** React、TypeScript、Vite、Tailwind CSS、Dexie、Zod、Vitest、vite-plugin-pwa。

**Spec:** `docs/superpowers/specs/2026-10-13-mvp-design.md`

## Global Constraints
- 所有使用者介面繁體中文；獨立開發分支，不修改 main。
- 不使用真實 AI、不建立付費服務、不部署、不放入 API Key。
- 開源來源固定 commit，保留 MIT；保留現有 README。
- 環境不能安裝時，完成原始碼但把未執行檢查列為未完成。

## Review Focus
- 非有限／負數／空白輸入：拒絕保存。
- 重複保存與分析後換圖：不產生重複餐點或過期結果。
- 凌晨日期及歷史目標：以選定本機日期及目標生效日計算。
- DB 寫入失敗：保留草稿並顯示錯誤。
- 重新打開、修改與刪除：指定紀錄正確更新，其他紀錄保留。

## Task 1: 核心模型與計算
Files: `src/domain/{types,nutrition,dates}.ts`, `tests/core.cases.ts`, `tests/core.{node,vitest}.test.ts`。
Interfaces: FoodItem、Meal、Goals；sumNutrition(items)、scaleItem(item, grams)、dailyTotals(meals, date)、goalForDate(goals, date)。
- [ ] 寫測試：兩餐 500 kcal／30 P／50 C／20 F => 1000／60／100／40；改重量 100→150 => ×1.5；錯誤重量拋例外；本機日期、目標選取、跨日期及不修改原資料。
- [ ] 執行 runner 記錄 RED；環境受阻時記錄不能驗證。
